# 솔로몬 저널 알림톡 — 켜기 전 준비 (원장님용)

솔로몬 저널을 게시하면(「올려」) 재원생 가족 중 구독한 분께 카카오 알림톡이 자동으로 나갑니다.
발송 함수·대기열·발송 기록은 소포스 입시 노트와 **함께 씁니다**(같은 Supabase 프로젝트 `gyuuimwalbxsocnamtqk`, `site='solomon'`).
채널·템플릿만 주니어솔로몬 것을 따로 만듭니다.

## 1. 원장님이 직접 하실 일

| 순서 | 할 일 | 어디서 |
|---|---|---|
| 1 | 주니어솔로몬 카카오톡 채널(pf.kakao.com/_xadGxnxb) 비즈니스 인증 | 카카오 비즈니스 (business.kakao.com) |
| 2 | 솔라피 계정 — 소포스와 같은 계정을 씁니다 (새로 가입하지 않음) | solapi.com |
| 3 | 솔라피에 주니어솔로몬 채널 연동 → 발신프로필 ID(pfId) 생성 | 솔라피 > 카카오 채널 |
| 4 | 아래 '알림톡 템플릿'을 등록하고 심사 요청 | 솔라피 > 알림톡 템플릿 |

- 심사 전 솔라피에 확인할 것: **"재원생 가족이 구독 신청한 솔로몬 저널 새 글 안내"가 알림톡(정보성) 템플릿으로 승인 가능한지.**
  반려되면 광고성 메시지(브랜드 메시지)로 바꿔야 하고, 그 경우 '(광고)' 표기·야간 발송 제한 등 규정이 달라집니다.
- 개인정보 처리방침 위탁 업체 칸의 '솔라피'는 계약서의 정확한 상호로 바꿔야 합니다.

## 2. 알림톡 템플릿 (심사 신청용 — 변수 이름을 바꾸지 마세요)

- 템플릿 이름: 솔로몬 저널 새 글 안내
- 메시지 유형: 기본형
- 본문:

```
[솔로몬 저널]
신청하신 솔로몬 저널에 새 글이 올라왔습니다.

■ #{제목}

#{요약}

■ 솔로몬 노트
#{노트}

※ 재원생 가족 중 솔로몬 저널 받아 보기를 신청하신 분께 보내 드립니다. 회원 화면 「내 정보」에서 언제든 끄실 수 있습니다.
```

- 버튼: 웹링크 · 이름 「솔로몬 저널 보기」 · 주소 https://juniorsolomon.com/journal.html (모바일·PC 같음)
- 변수 `#{제목}` `#{요약}` `#{노트}` 는 소포스와 같은 이름이어야 합니다. 발송 함수가 두 사이트에 같은 이름으로 채워 넣습니다.

## 3. 설정 값 넣기

1. 소포스 저장소의 `supabase/입시노트_알림톡_설정.sql` 이 이미 실행되어 있어야 합니다(소포스 쪽에서 실행).
2. 이 저장소의 `supabase/솔로몬저널_재원기준.sql` 을 Supabase > SQL Editor 에서 실행합니다.
   → 솔로몬은 **회원 승인 + 자녀 승인**이 된 학부모를 재원생 가족으로 자동 판정합니다. 원장님이 따로 한 번 더 승인하지 않습니다.
3. Supabase > Edge Functions > Secrets 에 두 값을 추가합니다(나머지는 소포스 때 넣은 값을 같이 씀).

| 이름 | 값 |
|---|---|
| SOLOMON_PFID | 솔라피의 주니어솔로몬 발신프로필 ID |
| SOLOMON_TEMPLATE_ID | 심사 승인된 '솔로몬 저널 새 글 안내' 템플릿 ID |

4. GitHub 저장소 **esther815/juniorsolomon-site** > Settings > Secrets and variables > Actions 에
   `NEWS_DISPATCH_URL` = `https://gyuuimwalbxsocnamtqk.supabase.co/functions/v1/news-dispatch`,
   `NEWS_DISPATCH_SECRET` = 소포스에 넣은 DISPATCH_SECRET 과 같은 값.
   (이 두 값을 넣기 전에는 게시해도 발송 단계가 그냥 건너뜁니다.)
   **반드시 3번(SOLOMON_PFID·SOLOMON_TEMPLATE_ID)을 넣은 뒤에 4번을 합니다.** 순서가 바뀌면 솔로몬 기사가 대기열에서 오류를 내고,
   같은 날 아침 8시 묶음 발송에서 소포스 기사까지 멈출 수 있습니다.

## 4. 켜는 순서

1. 지금은 시험 모드입니다. 위 1~3을 마치기 전에는 학부모께 아무것도 나가지 않습니다.
2. `ALIMTALK_MODE=test` 상태에서 원장실(sophosedu.co.kr/director.html) > 주니어솔로몬 칸 > **시험 발송** → 원장님 휴대폰으로 오는지 확인.
   (원장실 화면은 소포스 저장소 담당 채팅이 만듭니다.)
3. 재원생 학부모가 회원 화면 「내 정보」 > 「솔로몬 저널 받아 보기」에서 번호·동의를 입력합니다.
4. 이상 없으면 `ALIMTALK_MODE=live`. 이 값은 소포스와 함께 바뀝니다. 이후 「올려」 = 게시와 동시에 발송.

## 5. 동작 규칙

- 보내는 대상: 회원 승인 + 자녀 승인이 된 학부모 **그리고** 본인이 구독을 켠 회원만.
- 회원 승인이나 자녀 승인이 풀리면 구독도 자동으로 꺼집니다.
- 같은 기사는 같은 사람에게 한 번만 갑니다. 이미 올린 기사를 고쳐도 다시 나가지 않습니다.
- 밤 9시~아침 8시에 게시하면 다음 날 08:05 에 보냅니다.
- `test` 기간에 올린 기사는 `live` 로 바꾼 뒤에도 학부모께 다시 나가지 않습니다.
- 발송을 잠시 멈추려면 `ALIMTALK_MODE=off` (소포스도 함께 멈춤), 솔로몬만 멈추려면 이 저장소 Actions 변수 `NEWS_DISPATCH_ENABLED=false`.

## 6. 확인이 남은 것

- 퇴원생 학부모: 퇴원 뒤에도 자녀 승인이 'approved'로 남는다면 자동으로 빠지지 않습니다. 퇴원 처리 방식을 확인한 뒤 판정 규칙을 보완합니다.

## 하루 1통 묶음 발송 (원장 결정 2026-11-26) — 앱(발송) 채팅 작업 분담
원장 지시: **학부모에게 알림톡은 하루 최대 1통.** 기사가 여러 건 올라와도 한 번만 울리게 한다.

- **발송 시각(완료)**: `.github/workflows/news-dispatch.yml` 을 '하루 한 번(08:05 KST)만, 그날 새 기사를 모아 함수로 넘김'으로 바꿨다. 올릴 때마다 즉시 보내던 push 트리거는 제거. → 하루에 여러 번 울릴 일은 없음.
- **남은 일(앱/발송 채팅)**: 지금 함수·템플릿은 **기사 1건당 1통** 구조라, 하루 새 글이 N건이면 N통이 간다. 「한 통」으로 묶으려면:
  1. 요약형 알림톡 템플릿 신규 등록(카카오 심사): 예) 「[솔로몬 저널] 오늘 새 글 #{건수}건이 올라왔습니다. 대표글: #{대표제목} 외. 아래에서 모두 보기」 + 웹링크 버튼(journal.html).
  2. `news-dispatch` 함수가 한 번의 요청에 담긴 items 여러 개를 **한 통(요약형)으로 합쳐** 발송하도록 수정. items가 1건이면 기존 상세 템플릿, 2건 이상이면 요약형으로 분기.
  3. 소포스 입시노트와 **공용 함수**이므로, 소포스 발송에 영향 없는지 함께 점검(입시노트도 같은 묶음 규칙을 쓸지 원장 확인).
- 발송은 아직 **미가동**(비밀값 미설정). 위 1~2가 끝나고 비밀값을 넣는 순간부터 실제 발송된다.
